设计要点 / 与实现对齐

  • 数据：复用现有 git log，图表态额外请求 git.log-graph（带 %P 父提交哈希、--topo-order），客户端按父指针跑泳道布局。
  • 泳道布局：纯函数 layoutGraph(entries) —— 子在前父在后遍历，当前提交复用其首个父的泳道，新增父占最低空泳道；合并提交（2+ 父）在其节点行把第二父的泳道并回主干。
  • 渲染：一张 SVG 画布覆盖在提交行左侧，边先于节点绘制；不同泳道 stroke 取 var(--bsg-lane-N)；节点为圆点，合并提交为空心环。行高 28px、泳道间距 18px、首泳道 x≈20——密度对齐参考图，行更紧凑。
  • 颜色（令牌驱动）：泳道色相走局部自定义属性 --bsg-lane-0..5，6 色循环；皮肤覆写这些即可换色调，不碰面板表面令牌。色相略降饱和（与参考图色调一致：偏柔），蓝色为 #5fa8ff、琥珀为 #f5a55a、紫色 #b685e6 用于 HEAD/root 节点装饰。节点描边用 --dsw-alias-bg-layer-1 形成「环切」。
  • Ref 装饰精简：本图把分支胶囊移除——泳道本身即表达所在分支，颜色靠节点+连线；HEAD 改为 紫色 ring 节点。tag 仍保留绿色方角 chip（数据无可替代）。
  • 高亮衰减：当前选中行用 interactive-bg-active；涉及到严重告警的提交（如 fix 关键故障）允许补充半透明红色背景，参考图中红框行示意。
  • 交互：行点击/右键菜单与现有列表态完全一致（查看差异、复制哈希、revert、cherry-pick）——只是左侧多了泳道画布。列表 / 图表 切换持久化在 SidebarPrefs（新增 gitHistoryView: 'list' | 'graph'，缺省 list）。
  • 懒加载：沿用 LOG_BATCH 分页；图表态 loadMore 请求 git.log-graph 并把新页并入 SVG（边随节点一起增量绘制）。
